# Сигнатурный скан вместо жёстких оффсетов

**Статус:** `ready` — решение принято, заблокирован на входных данных от пользователя.

## Зачем

Сейчас оффсет флага зашит в скрипт, а билд опознаётся по `ModuleMemorySize`. Любой
патч меняет размер модуля, скрипт отказывается работать, и починка требует ручного
захода в Cheat Engine. Патч 03.09.2026 это уже продемонстрировал: образ вырос на одну
4К-страницу, флаг остался на месте, но скрипт встал.

Цель — чтобы адрес флага вычислялся в рантайме и большинство патчей переживались без
вмешательства.

## Как это работает

Флаг — статический глобал. На x64 код обращается к таким через RIP-относительную
адресацию: инструкция содержит не абсолютный адрес, а `disp32` относительно себя.
Условно:

```asm
C6 05 xx xx xx xx 01     mov byte ptr [rip+disp32], 1
```

При патче байты инструкции обычно не меняются — меняется только `disp32`, потому что
поехал образ. Значит якорем надо брать код, а адрес выводить из него:

```
target = адрес_следующей_инструкции + disp32
```

Сканируем модуль по байтовому паттерну с маской на четырёх байтах смещения, находим
инструкцию, читаем `disp32`, считаем адрес.

Библиотека не нужна: `SignatureScanner` и `SigScanTarget` есть в самом LiveSplit
(`LiveSplit.ComponentUtil`). [asl-help](https://github.com/ero-qt/asl-help) удобнее, но
тянет внешнюю зависимость — для одной сигнатуры это перебор.

## Архитектура

Скан не заменяет таблицу билдов, а дополняет её вторым эшелоном:

```
init:  размер модуля есть в vars.BUILDS?  → проверенный оффсет (быстро, детерминированно)
                              нет?        → сигнатурный скан
                    скан нашёл одно?      → работаем, разово предупредив, что билд
                                            не проверялся, и попросив прислать оффсет
       не нашёл / нашёл несколько?        → отказываемся, как сейчас
```

Инвариант сохраняется: скрипт никогда не таймит молча по непроверенному адресу. Каждый
автоопределённый оффсет, который кто-то пришлёт, становится новой строкой таблицы.

**Страховка после вычисления адреса:** байт по нему обязан быть `0` или `1`. Если там
что-то другое — скан нашёл не то, отказываемся.

**Попутное упрощение.** Оффсеты сейчас живут в `state(...)`, а такие дескрипторы
статичны — вычисленный в рантайме адрес туда не подставить. Переходим на
`MemoryWatcher<byte>`: адрес считается в `init`, читается вручную в `update`. Это
убирает по дескриптору на каждый билд и объединяет оба пути в один.

## Чего это не решает

- **Не панацея.** Если 4A перекомпилируют функцию с другим распределением регистров
  или инлайнингом, байты изменятся и сигнатура умрёт. Реже, чем ломается оффсет, но не
  «никогда». Поэтому таблица остаётся: два независимых механизма, отказ одного
  покрывается другим.
- **Не помогает найти флаг впервые** — только отслеживать уже найденный через билды.
- **Выбор сигнатуры — компромисс.** Короткая даст ложные совпадения по 50-мегабайтному
  модулю, длинная сломается от мелочи. Подбирается на глаз, проверяется только на
  будущих билдах.

## Прогресс / возобновление

**Следующий шаг — за пользователем, на Windows-машине.** Нужен выхлоп из Cheat Engine:

1. Прицепиться к `MetroExodus.exe`, добавить `MetroExodus.exe+1659040` как `Byte`.
2. Правый клик → **Find out what writes to this address**.
3. Зайти в загрузку и выйти. Ожидаются одна-две инструкции: ставящая `1` и ставящая `0`.
4. По каждой — **More information** (сама инструкция и её адрес).
5. Двойной клик открывает дизассемблер. Забрать оттуда:
   - дизассемблер текстом, ~10 инструкций до и после;
   - сырые байты этого куска, 60–80 штук (Memory View → правый клик →
     `Copy bytes + addresses`);
   - адрес инструкции **в виде `MetroExodus.exe+смещение`**, не абсолютный — абсолютный
     из-за ASLR бесполезен.

Если **Find out what writes** не заводится (отладчик CE конфликтует со Steam-играми,
игра может вылететь): `Settings → Debugger Options` → **VEH Debugger**, либо
**Find out what accesses this address** — чтения тоже годятся как якорь, просто мусора
больше. Делать не во время рана: брейкпоинт подвешивает игру на каждом срабатывании.

**Критерий приёмки.** На билде `52641792` правильный ответ известен — `0x1659040`. Если
скан выдаёт ровно его, механизм валиден. Это проверяется сразу, не дожидаясь патча.

### Заодно, пока открыт Cheat Engine

Оба пункта к сигнатурному скану прямого отношения не имеют, но снимаются в том же
заходе и висят в хвосте с самого начала:

- [ ] **`buildid` и `LastUpdated`** из `steamapps\appmanifest_1449560.acf` (открыть
      блокнотом). В документации текущий билд опознан только размером модуля —
      `52641792`; нормального идентификатора билда у нас до сих пор нет. Нужно для
      разговора с модераторами и для истории патчей.
- [ ] **`.CT`-таблица в репозиторий.** Живёт только на Windows-машине, а она переживает
      перезапуски, потому что хранит `модуль+оффсет`, а не абсолютный адрес. Перед
      сохранением **пересобрать без `+0x3001CBB`** — этот байт выпилен из скриптов
      03.09.2026 как протухший после патча и вводящий в заблуждение.
